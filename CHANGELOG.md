# Changelog

All notable changes to this project are documented here.

## [Unreleased]

- **A project saved by another program is not written over:** the window keeps the mark of the project from the moment it opens or saves it, looks at it again after a question and just before the write, and refuses to keep the program when another program wrote the file meanwhile. It says so in the eight languages and offers to read the project again, to save a copy under another name or to close. 2 new tests.
- **Built against the tag v0.3.7 of EH3D-COMMON** (it was v0.3.3): every write of a project is checked once more just before the file is replaced.

- **A program is written in one step:** every output of the command line and of the window goes to a new file beside the real one and is renamed over it, so that a cut or a full disk leaves the old program whole and never half of a new one for the machine. A read-only file is not replaced, and a device or a pipe is written to directly.
- **The window asks before it removes a signature:** saving into a project that is signed, or whose branch `isocam/` is, shows what would be removed and writes nothing until it is agreed.
- 3 new tests.

## [0.1.8] - Safer project results, machine limits of drills and plots, and many more tests

- **The program of one side no longer takes the place of the other:** two copper layers with the same name but for the extension (`board.gtl` and `board.gbl`) were both kept as `iso-board.nc`, so the second silently replaced the first. When two layers would share a name, each is now kept with its whole name (`iso+board.gtl.nc`). A file name that two layers share is no longer chosen by guess with `--layer`: the path says which.
- **The limits of the machine reach every program:** a drill file or a plot of holes and a plot of the isolation were written without looking at the table of the machine; they are refused now when they leave it (`--force` writes them from the command line and says why). In the window, a program written with the box that forces it now says which limit it breaks instead of saying nothing.
- **The header names the layer that was really read:** the window took the SHA-256 of the header from whatever lay on disk at that name when it wrote (another file next to a project, or a layer changed since it was opened); it is the one of the bytes that were read.
- **Nothing is written over a project or over a file the run reads:** an output that ends in `.eh3d` is refused, and so is one that is the settings file, the table of marks, the height map or the table of tools.
- **The window says when keeping a program removed a signature** of the project.
- 8 new tests with invented projects and layers.

## [0.1.7] - Isolation programs straight from the shared project of the suite

- **The reading and writing of the job of an `.eh3d` project are shared:** they are the module `eh3d_project::manufacturing` of EH3D-COMMON, the same for every manufacturing program; the commands, the window and the files of a project do not change.
- **The project of the suite (`.eh3d`):** `project info FILE` shows the layers of the job (the branch `manufacturing/`, a `.eh3dproj` package) and the programs kept in the project, and `project isolate FILE` isolates each copper layer of the job (or the one named with `--layer`) into a program kept in the branch `isocam/` only, with a copy of the layer and a reference to the content of the job. A job that changes afterwards makes the programs out of date (exit 2). In the window, a dropped `.eh3d` file opens the copper layers of its job, chosen from a list, and the program can be saved back to the project; the words are in the eight languages and no person has looked at the window yet. 5 new tests with invented projects.
- The crate `eh3d-project` of EH3D-COMMON is now used; Rust 1.89 or newer is needed.
- **An artifact cannot be named `.` or `..`, nor with a character that reverses or hides text:** the name of a file kept on the server was cut to the last part of its path, but `..` (or `dir/..`) was a name of its own, and a right-to-left override could make a name read as another file; they are refused now. 34 new tests cover base64 against the standard, the media types, the pen map and the range of a plot, the times and the depths of a job, the settings text and damaged or huge drill files.
- The shared workflow checker (`tools/workflow_hygiene.py`) is the current one of the documentation hub: the filters under a trigger (branches, paths, types) are no longer read as events.
- **Built against the released shared library:** the workflows take the tag v0.3.3 of EH3D-COMMON instead of its main branch; EH3D-GERBERVIEWER is taken at the tag v0.1.0.

## [0.1.6] - Arcs fitted to the paths of the cut, the silkscreen layer engraved, a report of the job before it is cut with the tools checked against the crib and a check of the limits of the machine that sees where an arc bulges

- **Arcs fitted to the paths, within a tolerance:** `arc_fit_tolerance_mm` (0 by default, which keeps every piece straight so the programs stay the same text; 0.001 to 0.5 mm) replaces each run of short moves that lies on a circle with one `G2` or `G3` (`src/arcs.rs`, `gcode::write_fitted`). A run is replaced only when its farthest point from the circle plus the bulge of its longest piece stay within the tolerance, so an arc is never farther from the polygon than that; a run turns one way, at most three quarters of a turn, and a corner or an S bend ends it. `isolate` and the window say how many moves were saved and compare the length of the cut with arcs and as straight pieces; the program is walked by the interpreter of the suite, so the limits of the machine see where an arc bulges. It is for G-code only, is refused together with a height map and is a parameter of the window. Tests with a fixed seed draw circles of every size and keep the deviation under the tolerance, in inches too, and read the program back with no finding.
- **The silkscreen layer is engraved:** `eh3d-isocam silk LAYER.gto OUT.nc|OUT.dxf` (`src/silk.rs`) joins the strokes that touch end to end into runs, cuts a region round its edge and engraves them at `silk_depth_mm` (0.05 by default) with a tool of `silk_tool_mm` (0.2 by default); `silk_width_tolerance_mm` (0.1 by default) sets how far a stroke may differ from the tool before it is reported. It warns every time that the layer is cut into the board and not printed, tells the strokes drawn wider or thinner than the tool, and counts the stamped pads that are left out. A plot is refused and the limits of the machine apply as for the paths.
- **A report before the job, with the tools set against the crib:** `eh3d-isocam report LAYER.gtl` (`src/report.rs`) tells the passes, the paths, the length of the cut, the tools in the order they are used, the arcs, the time and the findings of the dry run, then sets each tool against the CSV table of the tool crib (`crib_file`; an end mill by its diameter, a V-bit or an engraver by the width it cuts at `depth_mm`) and adds the checks of the layer: places the tool does not fit, problem zones and design rules. The report is in the language of the system (eight languages) and the command ends with the exit code 2, which means a verification that is not passed, when there is anything to look at.
- **The window makes the same checks and report without a screen:** `Window::checks_text` and `Window::report_text` give the checks of the layer and the report of the job (with the table of the crib when it is given) in the language of the window, and `arc_fit_tolerance_mm` is a parameter of the window. The sentences are new in the eight languages; the buttons that call them are not written because the window has not been looked at on a screen.
- **The pictures of the README are new:** they were written again by the picture mode (`--shot`) of the published program.
- **Requirements with identifiers and tests that name them:** `docs/REQUIREMENTS.md` is the register of what the program must do, one row for each capability with an identifier (`ISOC-001` on), its state (planned, prototype, implemented or validated), how far it is (done, partial, pending or blocked), its evidence and the test that shows it; a capability that is not written names the test that will show it. `tests/reqs.rs` reads the table and fails when a test does not exist, when a state does not agree with the progress or the evidence, when `docs/STATUS.md` does not say the same numbers, when a README does not link the documents or when a document holds a date or a private reference. The five documents of the family (`docs/SCOPE.md`, `docs/REQUIREMENTS.md`, `docs/STATUS.md`, `docs/NOT_YET.md` and `AGENTS.md`) are in the repository and are linked from the eight READMEs.

## [0.1.5] - Send results to the EH3D server and a server status command

- **A server mode over the client of the suite:** the keys `server_address`, `server_token`, `server_machine`, `server_timeout_s` (1 to 120, 15 by default), `server_retries` (0 to 5, 2 by default), `server_mdns` (`off` by default) and `server_max_answer_mib` (1 to 256, 8 by default) are settings of the configuration file and of the command line (`--server-address HOST:PORT`), read with their ranges by `eh3d-serverclient` of EH3D-COMMON; a value out of its range is an error that says the line; the mode is off until `server_address` is set and the local work never depends on it.
- **`eh3d-isocam server status`:** shows the link (the token as `***`) and what the server answers at `/health`, with the refusals and the failures of the network told by their code in the language of the system (taken from `LC_ALL`, `LC_MESSAGES` or `LANG`).
- **`--to-server` keeps the output on the server:** the file that `isolate`, `drills`, `route`, `mask` or `rubout-area` writes is kept on the EH3D server as an artifact once it is written locally (one request, never repeated by the client); the option is refused before any work when there is no `server_address` or `server_token`, and a refusal of the server is told after the local file was written.
- **The report of a dry run can be kept on the server:** `simulate PROGRAM.nc --to-server` keeps the report as the artifact `PROGRAM.nc.report.txt` (plain text), even when the program has findings and the command ends with an error.
- **The artifact says what it is and how it was made:** its media type follows the file (G-code, HP-GL plot, DXF drawing, drill file, Gerber layer, picture, table or text) and its parameters carry the command, the width of the fine and the coarse tool, the depth and the feed.
- **The CI and the release build take `EH3D-COMMON` at `v0.2.5`:** the sibling that is checked out is the release that has the client of the server, and the manifest asks for `min_common` 0.2.5.

## [0.1.4] - Rounded corners, small cutouts left out and a cut kept inside the table

- **Rounded corners on the cut round the board, off by default:** `outline_corner_radius_mm` (0 by default, which keeps the corners as sharp as they are drawn; 0 to 100 mm) rounds every corner of the closed paths of the outline with an arc of that radius before the tool goes round it (`src/corners.rs`; the arcs are drawn in straight pieces no further than half a cell from the true arc). A corner whose sides are too short for the radius, since an arc takes at most half of each side, gets the biggest radius that fits; `route` says how many corners were rounded and warns about the ones that got less. It applies to `route` and to the cut of `plot_outline`, and is a parameter of the window. Nine tests in `src/corners.rs` check the area taken off a square, both ways round, the cut-down radius, straight joins and the radius of 0.
- **Small cutouts of the outline can be left out:** `outline_min_cutout_mm` (0 by default, which keeps them all; 0 to 1000 mm) leaves out of the cut the cutouts of the outline (a closed path inside an odd number of others, so an island inside a cutout stays) whose box has no side longer than it, such as the holes a drawing of the board has for marks that the tool of the cut should not mill. `route` tells how many were left out and the window says so in its notes. It is a parameter of the window and shares its tests with the rounded corners (six in `tests/outline_shape.rs`, through the shared job and the command line).
- **The cut round the board is checked against the table of the machine:** when the settings describe a table, `route` refuses a cut that leaves it, naming the path and the place it goes to, and `--force` writes it with a warning; the window refuses it too and writes nothing. Nothing is checked, as before, while no table is described.
- **The window tells what the shape of the cut did:** after saving the cut, its notes say how many corners got a smaller radius than asked for and how many small cutouts were left out, in the eight languages of the window, next to the note about the bridges that stay on a corner. `outline_corner_radius_mm` and `outline_min_cutout_mm` are in the outline group of its parameters, and a new test of the window covers the notes and the refusal of a cut off the table.
- **The picture of the window in the README is taken again with the newest build:** the sample layer after Compute paths, with the parameters of the tool at the left.

## [0.1.3] - A dry run and a path view in the window, the time of the G-code that isolate writes, bridges kept off the corners, clearing with rings and a move of the whole job on the table

- **Where the work goes on the table:** `offset_x_mm` and `offset_y_mm` (0 by default; -10000 to 10000 mm) move every output by the same amount, after the scale and the reference points: the paths of `isolate`, the holes of `drills` and the cut of `route` (the move is part of the one transform the three share), so that a job can be put anywhere on the table of the machine. The limits of the machine still refuse a program that the offset takes off the table.
- **Clearing an area with rings, and the table checked path by path:** `rubout_style = rings` (`lines` by default) makes `rubout-area` fill a box or the closed paths of a file with closed rings that follow the edge inwards (`src/clearing.rs`, an even-odd fill with the exact distance of the isolation passes): the first ring is half a tool from the edge, the next ones a step of `tool * (1 - rubout_overlap)` further in, and one more along the middle when a strip would be left; `rubout_ring_order` (`outside-in` by default, or `inside-out`) is kept in the G-code whatever `ordering` says. Rings do not cut to a layer. `rubout-area` also checks its paths against the table of the machine before writing (`machine::check_passes`): a path that leaves it is refused as `path N of M (pass P)` with the place it goes to, and `--force` writes it with a warning, for lines as well as for rings; a limit that is not set checks nothing.
- **Bridges kept off the corners of the cut:** `tab_corner_clearance_mm` (0 by default, which keeps the even spread of before; 0 to 1000 mm) moves a bridge that would fall on a corner along the path, in steps of a quarter of the clearance, to the nearest place where the path turns by no more than 20 degrees within the gap and the clearance on either side of it (`drill::add_tabs_clear_of_corners`). A bridge that finds no such place stays where it was; `TabReport::corner_bridges` counts them, `route` warns and the window adds a note. The window also takes `tab_min_length_mm` and `tab_corner_clearance_mm` as parameters, next to the number and the width of the bridges.
- **The path of the tool in the picture of the window:** the box "Show the path of the tool" walks the G-code the paths would be written as and draws what the machine would do instead of the bands of the passes (`src/toolpath.rs`, `Window::set_toolpath`): rapid moves in grey, moves down in red and every cutting stretch in a colour from blue to amber by its depth below Z 0, with arcs drawn as arcs and cuts at the same depth joined in one stroke; the zoom, the pan and "Fit" work on it. `depth_step_mm` is now a parameter of the window, so the steps of depth show as several colours.
- **The dry run in the window:** the button "Dry run" walks the G-code that the paths would be written as, with nothing written, and opens a window with its time, the box it moves in, the deepest cut and its findings, in the eight languages of the window; `Window::simulate` and `dry_run_text` do it without a screen. A new group of parameters, "Machine" (`rapid_mm_min`, `machine_profile`, `machine_x_mm`, `machine_y_mm`, `machine_margin_mm`, `machine_max_depth_mm` and `machine_max_rpm`, all with the defaults of the settings, which check nothing), gives the speed of the rapid moves and the limits that a program may not break; a broken limit is a finding of the dry run. The result is thrown away when the paths are worked out again.
- **`isolate` prints the estimated time:** when `rapid_mm_min` is above 0, the line `estimated time: ...` (cutting, going down and moving, without the waits of the spindle) follows the summary of the G-code that was written, from the same walk of the program that `simulate` makes; it is a new line of the standard output, only there when the speed of the rapid moves is set, and not for a plot or a DXF drawing. `simulate` and the new `simulate::run_checked` share the machine limits as findings.
- **The CI and the release build take the shared libraries at their newest releases:** the pins of the sibling repositories in the workflows are raised to the releases the program now needs, so that the build and the binaries of a release use them.

## [0.1.2] - Limits of the machine checked in the G-code, a dry run with its time, cuts in steps of depth along a height map, the depth from the width of a V-bit track and holes in a short order

- **Machine profile and safe limits for the G-code:** `machine_profile` (`none` by default; `ccd-mtc` is the 495 x 325 mm table of the Bungard CCD MTC and `ccd2-mtc` the 325 x 270 mm table of the CCD/2 MTC), `machine_x_mm` and `machine_y_mm` (a table of your own, or another size for the profile; 0 takes the profile), `machine_margin_mm` (the distance kept from every edge, 0 by default), `machine_max_depth_mm` and `machine_max_rpm` (the deepest cut and the fastest spindle; 0 does not check them). `isolate`, `rubout-area` and the window walk the G-code move by move with the interpreter of the suite before it is saved and refuse it with the line, the place and the number of moves made when a move leaves the table or comes nearer to an edge than the margin, the tool goes deeper than the limit or the spindle runs faster than it; `--force` writes it anyway and tells the reason on the standard error. A depth or a spindle speed of the job above the limits is refused when the settings are read. All of it is off by default, so nothing changes until a machine is described. The sizes of the tables are the ones of the documents of EH3D-DRILLPRO, the origin of the table is taken at a corner, and nothing has run on a machine. Seventeen tests (`src/machine.rs` and `tests/job_safety.rs`) cover the profiles, inches, relative moves, the margin, the limits, the settings file and the command line.
- **A dry run of a G-code program, with its time and its findings:** `eh3d-isocam simulate PROGRAM.nc` walks the program move by move with the interpreter of the suite and prints the number of moves, the length of the cutting and of the rapid moves, the box it moves in, the deepest cut and the time (cutting along the surface at the feed, going down at the plunge feed, the rapid moves at `rapid_mm_min` and the `G4` waits; the stops for a tool change by hand are counted and not timed; with `rapid_mm_min` at 0 the time says what is missing instead of guessing). It reports a rapid move into the material, a cut with the spindle off or with no feed, a program that does not end, the notices of the reader of the program and every limit of the machine settings that it breaks, each with its line; any finding makes the exit code 1. Arcs are measured by their arc length. The report is told in the eight languages of the suite (the language of the system, English for any other). Twelve tests (`src/simulate.rs` and `tests/job_safety.rs`) cover the times worked out by hand, arcs, the stops, each kind of finding, the eight languages, the limits and the exit codes.
- **Cutting in steps of depth:** `depth_step_mm` (0 by default, which cuts all the depth at once; otherwise 0.005 to 2 mm) makes every path be cut again at each depth, a step more each time and the whole `depth_mm` at the end. A closed path goes round again from its start and an open run is cut back the way it came, with no lift of the tool between the depths. Nothing changes while it is 0: the G-code is the same text as before.
- **Cutting along a height map of the table:** `--height-map FILE` (`heightmap_file`) reads the map that EH3D-AUTOLEVEL writes (`levelling 1`, a `grid x0 y0 x1 y1 cols rows` line and the heights in mm, a row of the grid on each line); the two programs share only that text file. The Z of every cut is the depth under the height of the table at that point, taken from the height at the place where Z zero was set (`heightmap_ref_x_mm`, `heightmap_ref_y_mm`, 0 by default), and cutting moves are left in pieces of at most `heightmap_max_segment_mm` (2 mm by default, 0.1 to 50) so that the Z follows the table along them; the safe height and the rapid moves stay where they are. A map with a point not measured, a short row or a number that is not finite is refused, and so is a table more than `heightmap_max_range_mm` (0.5 mm by default, 0.01 to 5) above or below its height at the zero, or a map with G-code in inches. The file is read with the size limit of every other file, the G-code says which map it follows, and the limits of the machine apply to the Z that results. The window follows the map too. Nineteen tests (`src/heightmap.rs` and `tests/depth_and_levelling.rs`) walk the G-code back with the interpreter of the suite and compare every Z with the surface.
- **The depth for the width of a V-bit track:** `--crib-fine-width-mm W` (`crib_fine_width_mm`, 0 by default, which keeps `depth_mm`; needs `crib_fine`) works out the depth at which the V-bit or engraver of the crib cuts a track `W` wide, `(W - flat) / (2 * tan(angle / 2))` to a ten-thousandth of a millimetre with the flat `crib_vbit_flat_mm`, and puts it in `depth_mm`; the other crib tools then cut at that depth, and a note on the standard error tells the depth. A width at or below the flat, above the diameter of the tool or below 0.01 mm, an end mill (which cuts the same width at any depth) and a depth that `depth_mm` does not allow are refused with the setting named. Five tests in `tests/crib.rs` check the depth against values worked out by hand and against the width it gives back.
- **A short path for the drill:** `drill_order` (`file` by default, which keeps the order of the file; `nearest` or `optimized`) orders the holes of a drill file or a plot of holes. The tools stay in the order they first appear in and the holes of a tool stay together; within a tool the nearest hole to where the drill stands comes next, starting each tool where the one before it ended and the first from `start_x_mm`, `start_y_mm`, and `optimized` then shortens each tool's path by turning stretches of it round while that makes it shorter (up to 600 holes of one tool; more stay in the nearest order). `drills` tells on the standard error how far the drill travels in the order written against the order of the file. Ten tests (`src/drill.rs` and `tests/files.rs`) cover a scrambled line of holes, the order of the tools, a seeded scatter where the shortened path is never longer than the nearest-hole one and the nearest-hole one never longer than the file, and the command line.

## [0.1.0] - Tool crib, width of a V-bit at depth and exit codes

- Tests with a fixed seed read damaged drill files, outlines, settings and tool tables (every cut and many copies with bytes changed) without a panic.

- The exit code follows the convention of the suite on the command line: 64 for a wrong use (an unknown command, option or setting, or something that is missing), 1 for a failure of the work.

- **Tools from the tool crib:** `--crib FILE` (`crib_file`) reads the CSV table that `eh3d-tools` exports (the five columns it needs, `id`, `name`, `kind`, `diameter_mm` and `tip_angle_deg`, in any order; the others are ignored; a byte order mark, Windows line ends, quoted names and the quote mark the crib puts before a name that starts like a formula are read), and `--crib-fine N`, `--crib-coarse N` and `--crib-route N` (`crib_fine`, `crib_coarse`, `crib_route`, 0 by default) take the tools with those numbers from it: the width an end mill, a V-bit or an engraver cuts with becomes `fine_tool_mm` or `coarse_tool_mm`, and the diameter of an end mill becomes `route_tool_mm`. Each replacement is told on the standard error. The table is read only when a tool is chosen; a drill, a laser or a nozzle, a number the table does not have, a V-bit for the cut round the board, a table with a missing column, a repeated number, a diameter outside 0 to 50 mm or an angle outside 10 to 170 degrees, and a tool number without `crib_file` are refused with the row or the setting named, and a crib tool that is too thin for `min_tool_mm` is refused by the name of the setting. `config` prints the settings as they are, without reading the table.
- **The width of a V-bit or an engraver at the depth of the cut:** `2 * depth_mm * tan(angle / 2) + crib_vbit_flat_mm` (0.1 mm by default, from 0 to 5), no more than its diameter and no less than 0.01 mm, cut down to a ten-thousandth of a millimetre so that the tool is never said to be wider than it is (30 degrees at 0.06 mm with the default flat: 0.1321 mm). The window does not use the crib yet.
- **A sample crib and 22 tests:** `examples/crib.csv` (two end mills, a 30 degree V-bit and a drill) and `tests/crib.rs` check the table with damaged input, the widths against values worked out by hand, the settings and the command line.

## [0.0.9] - Minimum tool, estimated time of the job, resolution of the plot file and the picture mode

- **The resolution of the HP-GL plots is a setting:** `hpgl_units_per_mm` (40 by default, from 10 to 1000) sets the units of a plot file to the millimetre, for the isolation plot, the cut round the outline and the plot of the holes alike; 4000 units are 100 mm at 40 and 40 mm at 100. The check that refuses a coordinate beyond 32767 units follows it and says the resolution in its message (327 mm at 100). Nothing changes while it is left at 40.

- **The thinnest tool is a setting, and `info` can estimate the time:** `min_tool_mm` (0.02 by default, from 0.02 to 10) is the thinnest tool any tool setting may name (`fine_tool_mm`, `coarse_tool_mm` and `rubout_tool_mm` when they are on, `net_tool_mm`, `rubout_lines_tool_mm`); a tool below it is refused with the name of the setting, and the gap that counts as a conflict and the tolerance that must leave a tool follow it. `rapid_mm_min` (0 by default, which gives no estimate; otherwise 100 to 100000) is the speed of the rapid moves, and with it `info` prints an estimate of the time of the job (cutting at the feed, going down at the plunge feed, and the travel and the rise at the rapid speed; the spindle wait and the tool changes by hand are not counted). Nothing changes while the two are left as they are.

- **Drill and routing files in the 2.4 format:** `--excellon-format 2.4` (or `excellon_format = 2.4` in the settings file; `auto` is the default and changes nothing) reads and writes the coordinates of a drill file, and writes those of the routing Excellon file of `route` (the same head, six digits, signs for negative positions and the same range check, sharing the code of the drill files), as two digits before the point and four after, six digits in inches (`X012340` is 1.2340 in), with the zeros as the header says (`INCH,TZ` or `INCH,LZ`). The file is read by the reader of the suite, which is given the format as the default of a file that says nothing; a file that states its own format (a `FILE_FORMAT` comment or `INCH,TZ,00.0000`) keeps it and is no longer read as whole mils. The written file says `INCH,TZ` and `FILE_FORMAT=2:4`. A position beyond 99.9999 in, a format that is not `auto` or `2.4` and the plain style of `ncd_isocam_style` together with 2.4 are errors with stable words, and a line number in an error is the one of the file.

- **Binaries for every system:** `release-binaries.yml` builds the program with its window for Windows (64 and 32 bits), Linux and macOS (Apple silicon and Intel), packs each one with the licence, the readme, the icon and the examples, writes `SHA256SUMS` and a build manifest, attests their provenance, verifies the artifact as a stranger would, prepares a draft release only after the owner approves it (a dry run is the default) and opens an issue `build-failed` when anything does not finish.
- **A picture mode for the window:** `--shot FILE.png` (built with `--features gui`) opens the window at the size of `--size WxH` (320 to 8192, 1180x760 by default), with `--theme forge|dark|light`, `--lang CODE` and the layer of `--open FILE`, waits `--wait N` frames (0 to 3600, 6 by default), saves what it drew as a PNG file and closes by itself. An existing file is never replaced unless `--replace` is given, the window keeps no settings in this mode, the exit code is 0 when the file was written, 1 when it was not (also when the picture does not come back within 600 frames) and 2 for wrong arguments, and a build without the window says so. The arguments are read by plain code with its tests.

## [0.0.4] - Plots as the original program wrote them, tolerance for pads, filling by contours and DXF output

- **Plots as the original program wrote them** (`hpgl_isocam_style`, on by default; off keeps the compact form): every point of a path is its own `PA`, lines are ended with CR LF after about 75 columns, `IN`, `VS` and `SP` stand on lines of their own, and the plot ends with `PU;` and `PA0,0;SP;`.
- **Tolerance only for pads** (`conflict_tolerance_scope = pads`; `all` by default, as before): a gap narrower than the tool by up to the tolerance is accepted only when a pad is beside it, every other gap is judged against the whole tool, and the thin-copper warning looks at pads alone.
- **Filling by contours** (`rubout-area OUT [LAYER.gtl] --contour FILE`, or `--area`; `rubout_fill_margin_mm`): the closed paths of a file are filled even-odd (an inner path is a hole) with back-and-forth lines of `rubout_lines_tool_mm`; with a layer the lines are cut to the copper, the whole tool lying on copper plus the margin.
- **The kind of an input file** (`kind FILE...`): Gerber with a format statement, old-style Gerber, Excellon, HP-GL, DXF or unknown; a layer that is really a drill file, a plot or a drawing (or a drill file that is a Gerber layer) is refused with a plain message that names what it is and what to do.
- **DXF output:** `isolate` and `rubout-area` write a DXF drawing (polylines in millimetres, one layer for each pass) when the output name ends in `.dxf`.
- **Plot of the holes with pens** (`drills IN OUT.plt`, `hpgl_pen_map = tool:pen, ...`) and **pen speed** (`hpgl_pen_speed_cm_s`, 0 by default = the plot is as before and the machine uses its own speed): each drill tool is a pen, the tools the map leaves out take the lowest free pens, and a non-zero speed adds `VS` to any plot.
- **Bridges on the cut of the board** (`tab_count`, `tab_width_mm`, `tab_min_length_mm`; 0 bridges by default): `route` opens each closed path into runs with a gap at every bridge, so the board stays held in the sheet; the cut stops half a bridge and half a tool short of the middle of the bridge, a path too short for a bridge is left closed and said so, and a bridge of less than 0.1 mm or pieces of less than two tools are refused.
- **One net by itself** (`isolate --net X,Y`, `net_tool_mm`): only the copper joined to the point (up to half a millimetre from it) is isolated, with its own tool.
- **Clearing an area with parallel lines** (`rubout-area OUT --area X0,Y0,X1,Y1`, `rubout_lines_tool_mm`, `rubout_lines_direction`, and `rubout_overlap`): back-and-forth lines whose tool reaches the edge of the area.
- **Six alignment holes and a special pattern** (`alignment_holes` 2, 3 or 6; `alignment_pattern` normal or special; `alignment_special_a_mm` 40 and `alignment_special_b_mm` 60 by default): six is the pair and the four corners outside the board; special puts the pair about the middle of the board, and six adds four more level with them.
- **A warning for a tolerance that is high against thin copper** (`tolerance_warning_margin_mm`, 0.05 by default): with a conflict tolerance, `check` and `isolate` list the tracks and rectangular pads thinner than twice the tolerance plus the margin.
- **Better guess of the format of an old-style Gerber layer:** it uses the units the file states and how big the board is (a short coordinate in inch is 2.3, not 1.3), and a list of apertures may give both sides in one cell (`60x40`).
- **Each dependency on a sibling repository by path says the version it needs** (`version = ">=0.0.1", path = "../EH3D-..."`), so Cargo stops at once when the sibling next to this one is older than the program expects.
- **Rectangular pens in the viewer:** a track drawn with a rectangular or obround aperture is now the swept rectangle (the segment and the pen, a polygon), not a round-ended line as wide as the narrow side of the pen.
- **Problem zones in `check`:** inner corners sharper than `problem_corner_angle_deg` and tracks that run between two pads nearer than `problem_track_gap_factor` times the tool are listed as warnings; both criteria are settings.
- **Wide tools only round pads** (`around_pads_min_mm`, 0 = off, as before): with a value above 0 every tool except the narrowest cuts only the rings round pads whose smaller side is at least that wide, and the narrowest tool does the rest (tracks and small pads), leaving out what the wider ones have cut when `trim_fine` is on.
- **Tolerance for small conflicts** (`conflict_tolerance_mm`, 0 by default: as before): gaps narrower than the tool by at most that much are accepted by `check` and `isolate`.
- **The distance of the alignment holes** is documented as the setting `alignment_margin_mm` (5 mm by default; 10 mm is what some other programs use).
- **Copper that is not drawn stops `isolate`:** a layer with macro apertures, clear polarity or step and repeat, which the reader cannot draw, is refused with the reasons (the cutter would go over pads that are not there); `--force` writes anyway.

## [0.0.3] - Forced isolation, optimization, scale and fiducials, solder mask, units and a preview

- **Forced isolation** (off by default, `forced_isolation = yes`): a path is also laid along the middle of every gap that the finest tool does not fit in, as long as the gap is not narrower than `forced_min_gap_mm`; every place is reported with its coordinates and its gap, the narrower gaps are listed and left alone, and `isolate` still refuses to write for those unless `--force` is given. With the setting off, the places are only reported, as before. The tool is wider than such a gap, so it touches the copper on both sides there; that is only warned about, with the place.
- **Lighter paths** (`optimize_tolerance_mm` = 0.01 and `spike_max_mm` = 0.02 by default, 0 switches each off; `spike_angle_deg`): spikes where the path turns back on itself are taken out, repeated points are joined and points on a straight line within the tolerance become one move; arcs are not fitted, by decision: the paths stay straight moves.
- **Scale and correction of the board:** `scale_x` and `scale_y` scale the work about the centre of the board (the centre stays where it is, and a scale of 1 changes nothing), and pairs of reference points, given relative to that centre (`--fiducial "DESIGN_X,DESIGN_Y,MEASURED_X,MEASURED_Y"`, two or more times) give a similarity (two pairs) or a least-squares affine fit (three or more) applied to every path, hole and outline; a fit that turns the board over, collapses it, scales an axis more than `fiducial_max_scale_deviation` away from 1 or leaves a mark more than `fiducial_max_residual_mm` from where it should be is refused with the reason.
- **Solder mask:** `mask COPPER.gtl OUT.gts` writes the openings as a Gerber layer, from the mask layer of the design (`--mask-layer`) or from the flashed pads of the copper, each grown by `mask_margin_mm` (negative shrinks); tracks stay covered. Silkscreen is not produced.
- **Units:** a length in the settings file or on the command line may carry `mm`, `mil` or `in` (`--fine-tool-mm 8mil`), a bare number is in `input_units`, the G-code can be written in inches (`output_units = inch`, `G20`) and the lengths printed on the screen follow `report_units`.
- **Preview without a window:** `preview LAYER.gtl [OUT.svg|OUT.txt]` draws the copper and every pass (as wide as its tool) as an SVG drawing, or as text with a key (`preview_cols`).
- **Fixed:** a layer with a coordinate that is not a number is refused with the number of the shape instead of being drawn.
- **91 tests** run on a computer, with damaged input; none of this has run on a machine, and the correction has not been compared with real measurements.

## [0.0.2] - Excellon, several tools, direction and order of the cuts, alignment holes and design rules

- **The order of the paths is optimized by default** (`ordering = optimized`: nearest first and then shortened by turning stretches round, with the limit of `optimize_max_paths`); `ordering = nearest` and `ordering = original` still choose the others.

- **Holes and board outline:** drill files are read (Bungard files in mils with the reader of the Bungard formats, metric and decimal files with the reader of the suite) and written back in whole mils; a board outline is read from a Gerber outline layer, a DXF drawing or an HP-GL plot file, strokes drawn one by one are joined into closed paths, and the path of the tool round the board and inside its cutouts is written as HP-GL or as a routing Excellon file (`drills` and `route`).
- **Several tools and the leftover copper:** up to four tools, the widest cutting first; a stretch of a narrower tool that a wider one has already cut along is left out and the rest is kept as open runs; rings of a wider tool, each overlapping the one before, clear the copper that is left beyond the passes; the G-code stops for a tool change when the width changes and the plot file gives each tool its pen.
- **Direction, start and order of the cuts:** the paths are traced with the copper on the right of the tool; the direction can be climb, conventional, clockwise or counterclockwise, each closed path can start at its nearest point, its lowest point or where it was traced, the tool starts from a chosen point, and the paths are put in the order they were traced, nearest first, or shortened further by turning stretches of the order round; `info` shows how many paths go each way and the travel through the air.
- **Both sides, panels and alignment holes:** the layer, the holes and the outline are turned over, turned by quarter turns and repeated on a panel together; alignment holes are put where a turned-over board finds them again.
- **Design rules:** copper narrower than the rule, pieces of copper closer than the rule or than the tool is wide, and holes with too little copper round them, each with its place (`drc`).
- **One settings file:** every tuned value is a setting with a default, read from a `key = value` file (`--config`, `examples/isocam.cfg`, printed by `config`) or given as an option with the same name.
- **Fixed:** a region with fewer than three points no longer stops the drawing of a layer.
- **60 tests** run on a computer, with damaged input; the Rust version needed is now 1.88 (the Bungard formats).
